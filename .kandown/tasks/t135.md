# Fix CLI TUI duplicated/glitchy terminal rendering

## Context

The CLI TUI can visually glitch and duplicate board output in the terminal. The goal is to make the terminal interface behave like a fixed, clean fullscreen TUI similar to OpenCode: one stable screen, no serial duplicated redraw artifacts.

User also asked to inspect Herdr's terminal drag/drop implementation and refactor Kandown's TUI to support real mouse drag/drop of tasks between columns.

## Subtasks

- [x] Reproduce the duplicated/glitchy TUI output in a tmux-backed user project
  report: Launched `/tmp/kandown-tui-glitch-1780591754` in tmux and stressed reload/navigation. The current board renders as a short non-fullscreen Ink output, which relies on line-erasing diff output and can leave duplicated/scroll artifacts in some terminals.
- [x] Identify whether the issue is alternate screen handling, Ink output, mouse mode, or lifecycle cleanup
  report: The TUI manually enters alternate screen with raw ANSI instead of using Ink's `alternateScreen`, does not force a full-height frame, and mouse mode writes raw stdout from a hook. These are exactly the fragile paths that can corrupt a clean fixed TUI.
- [x] Inspect Herdr's terminal drag/drop implementation
  report: Cloned `https://github.com/ogulcancelik/herdr` to `/tmp/herdr-src`. Their pattern is SGR mouse parsing into Down/Drag/Up, a press state, a drag state activated after movement threshold, a hover/drop target, a rendered drop indicator, and commit-on-release.
- [x] Patch TUI rendering to use a stable fullscreen/clean redraw strategy
  report: Switched TUI startup to Ink's managed `alternateScreen`, added a fixed-height root frame, routed mouse ANSI writes through Ink's stdout helper, and enabled SGR button-motion tracking for drag events.
- [x] Add real TUI task drag/drop between columns
  report: Refactored board mouse handling around Herdr-style `MousePressState` and `TaskDragState`. Pressing a task arms a click, dragging activates drop mode, hovering highlights target columns, and releasing over another column writes the markdown status via `moveTaskToColumn`.
- [x] Retest in tmux with navigation/reload/move flows
  report: Built CLI, launched `/tmp/kandown-tui-dnd2-1780592300` in tmux, simulated SGR mouse drag from Backlog to Todo, verified `t3.md` changed to `status: Todo`, verified click still opens context menu, and verified keyboard move still sends `t3` back to Backlog.
- [ ] Build, bump patch version, tag, push, and verify npm publish
