# Add per-project web daemon and polish the TUI UX

## Context

User wants the web server to be a real per-project daemon. Running `kandown` should start/reconnect that daemon by default, the web UI should continue to work after quitting the TUI, and the daemon should be controllable from the TUI. Also improve the TUI visual design and make it more user-friendly.

## Subtasks

- [x] Design per-project daemon metadata and lifecycle (`start`, `stop`, `status`)
  report: Added `.kandown/daemon.json` with pid/port/url/project/version metadata, `/api/daemon` validation, and CLI lifecycle helpers. New installs ignore `daemon.json` via `.kandown/.gitignore`.
- [x] Refactor CLI startup so `kandown` starts/reconnects the daemon by default
  report: `kandown` now refreshes `kandown.html`, starts/reconnects the per-project daemon, opens the daemon URL, and launches the TUI without tying server lifetime to TUI lifetime.
- [x] Add TUI daemon status + start/stop controls
  report: Board TUI shows web daemon ON/OFF + port/URL and `d` toggles stop/start. Restart preserves the last custom port discovered from daemon metadata.
- [x] Polish board TUI colors, header, columns, status bar, and hints
  report: Added a stronger KANDOWN header, daemon status pill, column accent colors, improved status bar, clearer hints, and friendlier daemon messaging.
- [x] Test daemon lifecycle in an empty project with tmux/curl/browser-compatible API
  report: Verified `daemon start/status/stop`, `/api/daemon`, default `kandown` daemon startup, TUI `d` stop/start, custom port preservation, and daemon survival after quitting the TUI.
- [x] Build, bump, tag, push, and verify npm publish
  report: Minor bump to v0.8.0 started after the daemon/polish feature; final npm verification is tracked in the release workflow output.
