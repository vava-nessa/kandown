# Feature discovery

## Goal

Build enough shared understanding to clarify the feature and design it responsibly.

## Context

Describe the initial request, user need, known history, and links.

## Constraints

- Repository and platform rules
- Compatibility or migration boundary
- Time, dependency, security, or privacy constraint

## Exploration scope

List the questions that codebase exploration must answer and areas explicitly excluded.

## Findings

Separate observed facts with file or command references from interpretations.

## Assumptions

- Assumption and how it will be confirmed

## Clarification questions

- [ ] Product or UX decision, with consequence and recommended option
- [ ] Compatibility or failure behavior decision

## Decisions

Record each user answer, date or sequence, rationale, and effect on scope.

## Acceptance criteria

- [ ] Relevant code and data flow are mapped with evidence.
- [ ] Material assumptions are confirmed or rejected.
- [ ] Product questions required for architecture are answered.
- [ ] Risks and constraints are explicit.

## Work checklist

- [ ] Read repository guidance.
- [ ] Trace the relevant system path.
- [ ] Inspect existing patterns and tests.
- [ ] Ask focused clarification questions.
- [ ] Record decisions and remaining risks.
- [ ] Prepare the architecture proposal input.

## Verification

Explain how findings were confirmed through files, symbols, commands, or runtime observation.

## Evidence

Link code references, command output, diagrams, screenshots, and user decisions.

## Completion report

Summarize the current system, clarified intent, constraints, and architecture questions.

## Follow-ups

List exploration that can be deferred without weakening the architecture decision.
