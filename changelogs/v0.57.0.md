# 0.57.0 - 2026-09-05 - "Beautiful Agents"

The agentic feature set is complete: the live agent chat now runs the full
BeautifulUI catalog it was designed around, the autopilot got its guardrails
locked by tests, and the round 6/7 polish (component gallery, translations)
landed on top.

## Added

- **The agent chat is 100% BeautifulUI.** Every surface of the sidebar now
  renders through the shared components in `src/components/bui/` instead of
  lookalikes: the pixel-grid loader with elapsed timer for waiting turns, the
  reasoning trace fed by real thinking events, Tool Chips rows with command and
  file excerpts plus an ok/failed counter, Approval Cards for ```options blocks
  (one-click radio answers with auto-advance), Recommendation Cards for
  `PROPOSE:` lines, Context Cards above mentioned tasks, follow-up suggestions
  in the catalog style, and the official Prompt Bar composer with its @ task
  menu, /skills menu, model menu, Steer/Queue delivery control and stop square.
  Every component keeps its demo mode, so the hidden `#bui` gallery still
  showcases the original fixtures.
- **The complete BeautifulUI catalog is ported.** The scoped gallery now carries
  the whole component set (chat, lists, forms, navigation, data display), not
  just the chat subset.
- **Model menu for the ACP harnesses.** opencode and gemini get suggestion
  shortlists in the model menu. The gemini pick is forwarded to the spawn as
  `--model` (verified against the real CLI); opencode stays on Default for now
  because its `acp` command rejects unknown flags.
- **Edit presence survives a reload.** A new `GET /api/agent/active-edits`
  endpoint answers the daemon's live (session, task) editing pairs, and the web
  app seeds from it once per page load, so border beams and blobatars are back
  on the cards the moment the board opens instead of after the next agent edit.

## Fixed

- **ACP yolo sessions no longer stall on a persistent allow.** The inline
  permission auto-answer only picked `allow_once`; an agent offering just
  `allow_always` received a cancelled outcome and the turn hung. Both answer
  paths now share the same option priority.
- **Autopilot respects the dependency gate when re-filing orphans.** A task
  orphaned mid-column whose dependency had been regressed was re-queued at run
  start anyway, handing a blocked task to a session that the directives tell to
  never bypass a dependency. Gated orphans stay visible in the snapshot's
  orphan list for a human decision.
- **Eleven UI strings that the code referenced but `en.json` never defined**
  now exist (the header List toggle rendered its raw key, bulk-select
  aria-labels read "bulk.select" to screen readers, and eight more), and were
  translated across all 47 locales together with the seven new round 7 chat
  keys (846 additions since 0.56.0). The same pass realigned 49 translations
  of the agent settings surface with their current English copy, and four
  source strings lost their em-dashes.

## Changed

- The ACP permission routing surface (request extraction, deferred reply
  building, edit-like classification, routing verdicts, yolo auto-answer) is
  locked by 26 unit tests.
- The autopilot orphan re-file order is locked by 7 tests: orphans first
  (crash recovery), then ready tasks by priority and numeric id.
