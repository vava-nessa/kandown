# 0.55.0 - 2026-09-05 - "Agent Control Tower"

Agent instructions now come from the CLI at the moment they are asked for, and
from nowhere else. The generated instruction documents Kandown used to write into
your project are deleted, and `kandown work` is the single way an agent gets the
rules of the version you actually have installed.

## Added

- **Agent harness runtime.** Kandown drives the coding-agent CLIs already
  installed and authenticated on the machine (claude, codex, pi, and any
  Agent Client Protocol agent such as opencode or gemini) through four
  protocol adapters normalized into one nine-type event model. Sessions run
  with the compiled `kandown work` document as their initial prompt, stream
  over per-session SSE with history replay, and can be stopped at any time.
  Permission modes (`yolo` by default, `accept-edits`) map onto the harness
  native modes where they exist and degrade to advisory elsewhere.
- **Web chat sidebar.** A collapsible right-hand sidebar (fullscreen on
  mobile) talks to those harnesses: streaming markdown answers, a single
  live activity block per turn (thinking ticker plus every tool call with a
  command or file excerpt and an ok/failed summary), task references that
  open tasks in the same view, a `[show: tXXX]` directive that auto-opens a
  task and scrolls to it with the session's floating blobatar, `@t271`
  mentions that ship the integral task file to the harness, `/skills` with a
  read-only skills modal, a model picker per harness, and steer or queue
  delivery for follow-up messages on interactive harnesses. Conversations
  are indexed (never stored) under `~/.kandown/sessions/<project-hash>/` and
  resume through the harness native resume id.
- **Live editing experience.** While a harness edits a task, its card wears
  an animated border beam, the real blobatar (npm package, MIT) floats over
  card and editor, the editor locks read-only and shows a live green/red
  diff fed by the daemon file watcher. ACP harnesses in accept-edits mode
  surface Approval Cards; a project outside git gets an advisory.
- **Skills as chat buttons.** Skill manifests gain optional `chat.*` fields
  (button, task/board scope, interactive, autoApply) validated by the
  existing pipeline. Two built-in skills ship: `refine` (one-shot rewrite)
  and `grill-me` (interactive interview with an answer form in the chat).
- **Autopilot.** A preset that reads the board, dispatches harness sessions
  onto ready tasks (dependency-aware readiness, priority queue, configurable
  parallelism), hands completion reports downstream, enforces per-session and
  per-run token and cost caps, and stays stoppable from the sidebar, from any
  card, and through a global kill switch. Column moves stay behind the
  existing gates; the Done move is proposed, never forced.
- **Task mentions.** `@t271` in the chat input picks a task and ships its
  integral file content to the harness before the user line.
- **Write conflict guard.** Task saves carry the hash of the content the
  editor loaded; when the file changed since then the server answers 409 with
  the current content and the conflict modal opens, instead of silently
  losing an edit to a concurrent writer.
- **Agent UI translations** across all 47 languages.

## Removed

- **`.kandown/AGENT_KANDOWN.md` and `.kandown/AGENT.md` are gone.** `kandown init`
  no longer writes an agent instruction document into your repository, and nothing
  reads one. A file can be edited, forked and left behind by an update; a command
  cannot.
- **The repository's generated `AGENT_KANDOWN.md` and `scripts/sync-agent-kandown.js`**
  are deleted along with their build step, so the packaged authoring source is the
  only copy that remains and it never leaves `node_modules`.

## Changed

- **BREAKING: prompts that point at the old file must point at the command.**
  Anything that says "read `.kandown/AGENT_KANDOWN.md`" stops working. Replace it
  with `kandown work`, which prints the immutable core, the selected workflow,
  active skills, your project instructions and the live board context in one
  deterministic document.
- **Instruction files are migrated once, without losing your edits.** `kandown init`
  and `kandown work` rename `.kandown/instructions.md` to `.kandown/kandown_work.md`
  (and the same for the global `~/.kandown/` layer), delete a legacy agent document
  only after a checksum match against the generated original, and move any edited
  one to `.kandown/legacy-agent-docs/` instead of deleting it. Both scopes report
  what they did on stderr.
- **The `AGENTS.md` / `CLAUDE.md` bootstrap line is created and repaired in place.**
  Only the marker-owned line is touched, through an atomic write, so surrounding
  prose you wrote stays exactly as it was.
- **Settings, Agent, Kandown Work previews the real compiler output.** The legacy
  three-block, raw-template configurator is replaced by the exact shared document
  the CLI and the agent launcher render, with the immutable core shown as
  immutable.
- **Documentation.** Added [Upgrading from `AGENT_KANDOWN.md`](https://kandown.dev/docs/agents/instructions#upgrading-from-agent_kandownmd),
  a migration table covering every file the upgrade touches, and linked it from the
  installation page's breaking-change notice.

## Fixed
- **Task chips in the chat opened a new tab.** The URL sanitizer stripped the
  task protocol, so the chip fell back to an external link; it is now a real
  button on the in-app open path.
- **Streaming markdown leaked a stray code fence** while the answer was still
  arriving; dangling fences are closed before rendering.
- **Conflict resolution buttons were dead in server mode** (they required a
  directory handle the server never provides), exactly where the new write
  conflict flow lands.
- **Pi and ACP tool rows showed only the tool name.** They now carry a
  command or file excerpt, and a late-arriving detail patches the open row
  instead of duplicating it.
- **A stale daemon token showed the misleading "start the daemon" card.**
  The sidebar now distinguishes a dead daemon from a restarted one and offers
  a Reload button.

- **A refused move now tells you what is blocking it.** `kandown move t1 Done`
  used to print a generic `Move failed: t1` next to a stray `[kandown] …` log
  line; it now prints one sentence naming the reason, either
  `Cannot move t1 to Done: blocked by t2` or `Task not found: t1`. The MCP
  `move_task` tool returns that same sentence as its error, so an agent reads
  the actual blocker instead of guessing between three causes.
- **A task created with a custom, digitless id is no longer unreachable.**
  `kandown create "Assign me" --id assignable` wrote
  `assignable_assign_me.md`, and because a filename is only split at the
  underscore when the id part contains a digit, that file claimed the id
  `assignable_assign_me`. The task could not be shown, moved, assigned or
  depended on by the id it was created with. Such ids are now stored as a bare
  `assignable.md`. Ids allocated by Kandown (`t232`) and the usual custom
  formats (`BUG-001`, `custom-1`) keep their descriptive filenames.
