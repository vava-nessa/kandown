  ## Decisions

  - **Generate from JSDoc rather than write a map by hand.** The headers already
    existed at 95% coverage; the gap was aggregation, not authorship. Generating also
    means the map cannot drift, which a hand-written one always does — proven by the
    three features the deleted reports claimed as shipped but never built.
  - **Determinism is the whole mechanism.** No timestamp or version in the output, so
    `--check` can treat any diff as real drift. Verified byte-identical across runs.
  - **Two enforcement levels, deliberately different.** pre-commit warns (a hook that
    blocks WIP commits gets disabled); CI fails (branch protection cannot be skipped).
  - **`graphify-out/` gitignored, not committed.** 4.3 MB of generated JSON would
    conflict on every merge and costs 30 s to rebuild. It is a local query index.
  - **`core.hooksPath` over husky.** Same result, zero dependencies, hooks visible in
    review.
  - **CODEMAP and graphify are complementary, not redundant.** The map answers "what
    is this file" cheaply and in-context; the graph answers "what depends on what" on
    demand and stays out of the context window.

  ## Verification

  - `pnpm codemap` → 150 files, 100% documented; two runs byte-identical (md5)
  - `pnpm codemap:check` → passes
  - `pnpm typecheck` → clean

    non-blocking
  - all internal links in README / AGENTS / CODEMAP / docs resolve to real files

  ## graphify graph — resolved

  Adding `.graphifyignore` after a first build left a stale graph on disk: graphify
  refuses to overwrite when the node count drops sharply (a guard against losing chunk
  files), so the pre-ignore graph survived with 1140 nodes still sourced from the
  generated bundles. Rebuilding from scratch fixes it:

  ```bash
  rm -rf graphify-out && graphify update .
  ```

  to `src/lib/parser.ts:74` instead of the bundle — which was the whole point of the
  ignore file.

  📖 Note for anyone reading `graph.json` directly: it is networkx node-link format,
  so edges live under `links`, not `edges`.

# Agent-first documentation system

## Context

The codebase already carries excellent raw material: 137 of 144 source files have a
JSDoc `@file` / `@description` header, many with `@functions` and `@exports`. What
was missing was **aggregation and a freshness guarantee** — an agent arriving in the
repo had no index and had to glob 144 files to orient itself, and nothing prevented
any hand-written doc from drifting away from the code.

Three concrete problems this fixes:

1. **No entry point.** No codemap, no architecture document, no `docs/` directory.
2. **An actively misleading trap.** `bin/kandown.js` and `bin/tui.js` are tsup
   bundles generated from `src/cli/cli.ts` and `src/cli/tui.tsx`, committed because
   they ship in the npm package — 61 000 lines of generated code. `AGENTS.md`
   described them as if they were source. An agent edits the bundle, it works, and
   the next `pnpm build` erases the change. Same trap on `src/lib/version.ts` and
   the root `AGENT_KANDOWN.md`.
3. **No automation.** No git hooks at all, so every doc was maintained by hand.

## Subtasks

- [x] Write `scripts/build-codemap.js` — deterministic, no LLM, no new dependency
  report: Walks `bin/` + `src/` + `scripts/`, parses the leading JSDoc block of each
  file and emits `CODEMAP.md` (239 lines, one summary line per file grouped by
  directory with friendly area labels) and `CODEMAP.json` (same data plus
  `@functions` / `@exports` for symbol lookup). 150 files indexed, 100% documented.
  Output carries no timestamp, version or absolute path, so two runs are
  byte-identical — verified by md5. Locales collapse to one line; generated bundles
  are listed but never expanded. Three parser edge cases handled: a shebang or a
  `"use client"` prologue before the header block, and sentence splitting that does
  not break on `src/lib/parser.ts` (a period only ends a sentence when the next
  non-space character is not lowercase, which also handles the `📖` marker).
- [x] `--check` mode that fails when the codemap is stale **or** a source file has
      no `@description`
  report: `pnpm codemap:check`. Re-renders in memory and diffs against the committed
  files; exits 1 listing each problem. Wired into CI.
- [x] Add JSDoc headers to the 4 real files still missing one
  report: `src/lib/utils.ts`, `src/components/ui/button.tsx`, `input.tsx`,
  `textarea.tsx`. Coverage is now 100% and frozen by `--check`.
- [x] Versioned `.githooks/` installed via `core.hooksPath` from a `prepare` script
  report: `scripts/install-hooks.js` sets `core.hooksPath` to the tracked
  `.githooks/` and re-applies the executable bit; runs from `prepare`, so
  `pnpm install` is all a contributor needs. No husky, no new dependency, and every
  code path exits 0 so an install can never break. Deliberate strictness split:
  pre-commit regenerates and stages the codemap but only *warns* on a missing
  `@description` (blocking a WIP commit is how hooks get disabled), while CI runs
  `--check` and *fails*. Both hooks verified by running them directly.
- [x] Wire `graphify` for relationship queries, with `graphify-out/` gitignored
  report: `graphify update .` bootstraps and refreshes the graph AST-only — no LLM,
  no network, no token cost — in ~30 s for 152 files. `.githooks/post-commit` runs it
  detached, exits quietly when graphify is absent, and can never fail a commit
  (`KANDOWN_NO_GRAPHIFY=1` opts out). Added `.graphifyignore` excluding the generated
  bundles: without it the graph indexed `bin/kandown.js`, so `graphify explain
  parseTaskFile` pointed at the bundle instead of `src/lib/parser.ts`. The 4.3 MB
  output stays gitignored.
- [x] Write `docs/ARCHITECTURE.md`
  report: The hand-written companion to the generated map — the one-sentence data
  model, what lives on disk, the three entry points, how a change flows in each of
  the three modes (daemon, standalone File System Access, CLI/TUI), the shared pure
  core and why the parser round-trip is an invariant, the daemon's three hard-won
  lessons, the build pipeline with a generated-files table, the documentation system
  itself, and 8 numbered invariants.
- [x] Move the release runbook out of `AGENTS.md` into `docs/RELEASE.md`
  report: `docs/RELEASE.md` holds the full runbook (version system, mandatory
  pre-bump manual test, increment and naming, changelog rules, build, commit/tag/push
  with the changelog in the commit body, publish verification, recovery). `AGENTS.md`
  is now a 120-line router: read order, five hard rules, the Herdr dev-server
  workflow, and the command table.
- [x] Rework `README.md`
  report: Restructured around a prominent "For AI agents" section (`kandown work`,
  the output contract, MCP, agent launching) that was previously buried. Condensed
  the four feature tables into scannable prose, split the CLI reference by audience,
  added a contributor reading order, and fixed the broken anchor links in the old
  footer. Corrected two factual drifts: "5 built-in skins" → 38 themes, and three
  features the old docs claimed shipped that do not exist (see [[t245]]).
- [x] Delete the seven root plan documents once their open ideas are ticketed
