report: |
  ## Root cause

  Pressing `A` on a task and picking **opencode** launched a bare `opencode`
  command. OpenCode's default command (`opencode [project]`) takes a project
  *PATH* as its only positional — not a message — so the TUI booted with an
  empty composer and zero task context. The launcher did write a context file
  to `/tmp` and exposed it via `KANDOWN_CONTEXT_FILE`, but the opencode TUI
  never reads that var or file, so it stayed blank.

   ## Fix

  - **`src/cli/lib/agents.ts`** — opencode `buildCommand` now returns
    `['opencode', '--prompt', combined]`. `opencode --prompt "<message>"` uses the
    default TUI command with the initial prompt pre-filled, launching an
    interactive session with the task context loaded. The previous use of
    `opencode run --interactive` launched a non-interactive one-shot mode,
    resulting in a blank TUI.
  - **`src/cli/lib/agents.ts`** — bonus fix: gemini was using `-p/--prompt`,
    which Gemini's own help calls "non-interactive (headless)" — it ran the
    prompt then exited, contradicting the agent's `interactive: true` field.
    Switched to `--prompt-interactive` (`-i`) so Gemini runs the prompt and
    *continues* interactively, matching the other agents.
  - **`src/cli/lib/launcher.ts`** — the tmux split-window path now prefixes
    `env KANDOWN_CONTEXT_FILE=… KANDOWN_TASK_ID=… KANDOWN_DIR=…` so those vars
    reach the agent pane (a new tmux pane inherits the tmux *server's* env, not
    this process's overrides, so `execSync`'s `env` option alone never reached
    it). Keeps parity with the direct-exec path. Also updated the context-file
    comment: it's now a safety net for argv-length truncation rather than the
    primary transport (every agent receives the prompt as a CLI arg now).

  ## Verification

  - `pnpm typecheck` ✅ and `pnpm build` ✅ pass.
  - Round-trip test of the double shell-escaping (tmux path) confirms opencode
    receives the full prompt as one intact argv element (single/double quotes,
    backticks, `$VAR` unexpanded, newlines preserved) plus the three
    `KANDOWN_*` env vars.
  - End-to-end: launched `opencode run --interactive "<task prompt>"` in a tmux
    pane — the OpenCode TUI opened with the full task context loaded in the
    composer (no longer blank), BUILD agent selected, interactive session ready.

  Other agents (claude, codex, goose, aider) were verified against their CLIs'
  `--help` and are unchanged; goose stays non-interactive by design
  (`interactive: false`), aider keeps its standard `--message` one-shot pattern.
