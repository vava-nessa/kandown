## Goal

Ship kandown's extension system: a way for users (and coding agents) to add
custom task fields, web panels, CLI commands, transition gates and sync
integrations, without ever becoming a second source of truth. Spec lives in
`docs/EXTENSIONS.md`, decision in `docs/adr/0002-extensions-system.md`.

## Why now

Designed and documented in this session (EXTENSIONS.md + ADR 0002). The contract
is fixed; now build it for real, end to end.

## Scope

- Harden the serializer to round-trip nested `plugins.*` frontmatter (P0 blocker).
- Extension engine: types, manifest, host with isolation, contribution registry,
  `plugins.*` namespace helpers, permissions, restricted mode, trust prompt.
- All 5 contribution points: `field`, `webPanel`, `command`, `gate`, `sync`.
- CLI `kandown extension` (create / dev / install / list / enable / disable /
  purge) + dispatch of contributed commands.
- Web: extension panels in the Drawer (ErrorBoundary + scoped API), field editor
  in the task drawer, card badge, settings panel for enable/disable/install.
- Canonical example `examples/extensions/burndown` (field + panel + command +
  gate).
- Tests: serializer round-trip, host isolation, namespace read/write.

Out of scope this task: the kandown.dev submit-form backend (separate website
repo), npm publish of `@kandown/extension-api` (types ship inside the package for
now), the iframe-sandbox hardening pass (deferred per ADR 0002).

## Acceptance criteria

1. A nested `plugins.burndown.points: 5` survives an open/save round-trip
   (serializer no longer drops objects).
2. An extension that throws on load is marked `errored` and never breaks the
   board; an extension that throws while rendering is quarantined; the core keeps
   working.
3. The `burndown` example extension loads from `.kandown/extensions/burndown`,
   contributes a `points` field (editable in the drawer, badge on the card), a
   burndown web panel, a `kandown burndown` command, and a "no Done without
   points" gate that blocks the move with a reason.
4. `kandown extension create foo` scaffolds a working extension; `kandown
   extension install <path-or-url>` installs one; enable/disable/purge work.
5. Restricted mode is on by default; project-local extensions require a trust
   prompt before loading.
6. `pnpm typecheck`, `pnpm build`, `pnpm test` pass.

## Decisions

- **Runtime:** hybrid. Authoritative logic (gates, fields, sync) in Node once;
  rendering (panels, badges) in the browser. Single mutation authority preserved.
- **Web sandbox:** ErrorBoundary-only (Obsidian model), with a scoped API so
  extensions never get the raw daemon token or the React store. iframe deferred
  per ADR 0002.
- **Data:** opaque `plugins.<id>.*` namespace, round-tripped by the core.
- **Store:** community-curated GitHub index (`kandown/community-extensions`) +
  paste-URL + one-click + npm secondary. kandown.dev submit form is out of scope
  here (website repo).
