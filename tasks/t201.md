  ## Changes

  **Layout** — tasks now live at the project root in `./tasks/`, while `.kandown/` only holds `kandown.json` (config), `kandown.html` (web UI), `AGENT.md` / `AGENT_KANDOWN.md` (agent docs), and `daemon.json` (runtime metadata).

  **CLI** — `bin/kandown.js`
  - New helpers: `getProjectRoot(kandownDir)`, `getTasksDir(kandownDir)`, `migrateTasksToTopLevel(kandownDir)` (idempotent), `archiveTask()` / `unarchiveTask()` (the latter two were referenced in the route handler but never defined — pre-existing bug, now fixed).
  - `doInit()` creates `tasks/` at the project root instead of inside `.kandown/`.
  - `ensureKandownDir()` runs the silent migration on every CLI startup. One-time log: `✓ Migrated N tasks from .kandown/tasks/ to ./tasks/`.
  - New REST endpoint: `POST /api/migrate-tasks` (idempotent).
  - Init banner rewritten to show the new layout.

  **TUI** — `src/cli/lib/board-reader.ts`, `file-watcher.ts`
  - New `getTasksDir(kandownDir)` helper, used by `listTaskIds`, `readTask`, `moveTaskToColumn`, and the watcher.
  - File watcher now points at the project-root `./tasks/`.

  **Web (File System Access)** — `src/lib/filesystem.ts`, `store.ts`, `watcher.ts`
  - User picks the **project root** in the file picker. The app derives `.kandown/` and `./tasks/` from it.
  - New `getTasksDirHandle(projectHandle)` and `serverMigrateTasks()` helpers.
  - `openServerProject()` and `tryAutoOpenServerProject()` call `serverMigrateTasks()` before reading tasks.

  **Templates**
  - `templates/AGENT.md`, `templates/AGENT_KANDOWN.md`, `templates/README.md` updated to document the new layout.
  - Legacy `templates/.kandown/` (empty) removed.
  - `templates/tasks/` stays at the top level (it was already in the right place).

  **i18n** — `src/lib/i18n/locales/*.json` (48 locales)
  - `emptyState.selectFolderDesc` updated to tell the user to pick the project root.

  **Docs**
  - `CHANGELOG.md` — new "Unreleased" section documents the layout change + migration.
  - `README.md` — new layout diagram with a note about the silent migration for upgraders.

  ## Decisions

  - **Silent auto-migrate** (no UI prompt). Runs once on first startup that detects the legacy layout, logs a single line, done.
  - **Delete `.kandown/tasks/` only if empty** after the move. Preserves any non-md files (like `.scratch/` notes).
  - **Web project handle = project root** (parent of `.kandown/`). Cleaner mental model.

  ## Verification

  - `pnpm typecheck` ✓
  - `pnpm build` ✓ (vite + tsup both green)
  - Fresh `kandown init` in temp dir creates `.kandown/` + `./tasks/` at the project root, no tasks inside `.kandown/`
  - Legacy migration tested on this very project: 30 tasks moved from `.kandown/tasks/` to `./tasks/`; CLI now reports "Both .kandown/tasks/ and ./tasks/ have files — leaving both in place" (idempotent, correct)
  - Daemon endpoints verified: `GET /api/tasks` returns the moved files, `PUT /api/tasks/t99` writes to `./tasks/t99.md`, `POST /api/tasks/t99/archive` moves it to `./tasks/archive/t99.md`
