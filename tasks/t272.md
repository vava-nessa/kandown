## Goal

Make the existing OnboardingTour modal keyboard-accessible, i18n-ready, and
visually polished, then ship the new copy to every supported locale so first-time
visitors everywhere see their own language instead of hardcoded English.

## Why now

The component was shipped in v0.41.1 (`feat(onboarding): gate modal per-project
via ui.onboardingCompleted`) but only as a stop-gap: copy is hardcoded English,
no `role="dialog"`/`aria-modal`, no focus trap, no `Esc` to close, no backdrop
click, no Back button, and 48 of the 49 supported locales never got the new
settings keys. Time to finish what v0.41.1 started.

## Scope

- **Refactor the modal** to be a real accessible dialog (role/aria/focus trap/
  Esc/backdrop/Back button/live region announcement).
- **Extract copy into a new `onboarding.*` i18n namespace** in `en.json`.
- **Translate** the new keys into all 49 supported locales.

Out of scope: redesigning the visuals (icons + layout stay), changing the
step count (3 stays as 3), touching the TUI or CLI surfaces.

## Acceptance criteria

1. First-time visitors (project with no `kandown.json` or with
   `ui.onboardingCompleted: false`) see the modal automatically. It never
   appears again on that project unless the user re-opens it from Settings.
2. `Esc` closes the modal. Backdrop click closes it. `X` still closes it.
3. `Back` works on step 2 and step 3; step 1 hides it.
4. Focus is trapped inside the modal while open and restored on close.
5. Modal exposes `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, and
   `aria-describedby`. Step changes are announced via a polite live region.
6. All visible strings come from `useTranslation()` (`onboarding.*` keys).
7. All 49 locales (`en`, `fr`, `es`, `de`, `it`, `pt`, `ja`, `zh`, `ko`,
   `ar`, `ru`, ...) carry the new keys. Missing keys fall back to English
   cleanly (no missing-translation warnings in the console).
8. `pnpm typecheck` passes. `pnpm build` succeeds. `pnpm test` passes.
9. Settings → "Show onboarding tour" still re-opens the modal.

## Decisions

- **i18n shape:** nested `onboarding.*` object instead of flat `onboardingStep1Title`-style keys. Matches the `cheatsheet.*` / `emptyState.*` precedent in the same file.
- **No focus-trap library:** the project already handles `Escape` inline per component (`Drawer`, `CommandPalette`, `LanguageDropdown`, etc.). Adding a dep just for the tour would be overkill; a 15-line inline trap is enough.
- **Back button stays disabled on step 1** to avoid a useless click target — the close (X) already covers the "I changed my mind" case.
- **Step indicator** uses a polite live region so screen readers hear "Step 2 of 3" on transitions without stealing focus.
- **Settings re-open** keeps the current behavior: the `kandown:showOnboarding` event bypasses the `onboardingCompleted` gate and re-shows the tour. Closing it is a no-op write (flag is already `true`).
