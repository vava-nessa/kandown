# [website+app] GitHub stars badge in header & About card, link to changelog

## Context

The repo is public on GitHub; vava wants the social proof visible at a glance
without making it the centrepiece. Two surfaces to touch:

1. **Marketing site** (`website/`) — the global header, next to the existing
   GitHub icon. Small star + compact count (`★ 1.2k`), the whole pill
   linking to the repo.
2. **Kandown web app** (`src/components/settings/AboutVersionCard.tsx`) —
   the *About* section already shows the running version and update status;
   add a row for stars (same source as the site, so the two stay in sync)
   and a `Read the changelog for v0.X.Y` link that opens
   `https://kandown.dev/changelogs/v${currentVersion}` in a new tab. The link
   makes the version badge useful — right now it just sits there.

## Decisions

| Question | Decision |
|---|---|
| Refresh cadence | Client-side, `localStorage` cache with 24h TTL. GitHub API is CORS-friendly and the request is a few hundred bytes; a daily refetch is invisible to the visitor. No rebuild needed. |
| Number format | Compact for >999 (`1.2k`, `12k`), exact below (`123`, `42`). Same on both surfaces. |
| Loading state | Skeleton shimmer (`★ —`) until the value lands, so the badge does not pop. |
| Error / offline | Silently render nothing — the existing GitHub icon is the primary affordance, the badge is extra. |
| Header placement | The star badge lives *inside* the existing GitHub `<a>`, so the whole thing is one click target. Visual gap kept tight so it reads as one element. |
| Changelog link | `<a target="_blank" rel="noopener noreferrer">` opens `https://kandown.dev/changelogs/v${currentVersion}`. Unavailable in the demo build (`__KANDOWN_DEMO_BUILD__`) — guard with the same flag used for the live web app detection. |

## Notes

- Both surfaces use the same component (or a shared helper) so the count
  can never disagree. The marketing site fetches `kandown.dev` over the
  public internet; the app's fetch is the same endpoint with the same
  cache, just bundled in the app's React tree.
- The site already has GitHub/npm links in the header. The stars badge
  sits next to the GitHub one — the npm logo keeps its own row.
- `kandown.dev/changelogs/v${currentVersion}` works because the
  prerenderer followed the link from the changelog index on the last
  build, so the page exists and is shareable.
