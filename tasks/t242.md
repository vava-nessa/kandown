# Sanitize i18n strings passed to dangerouslySetInnerHTML

## Context

Three call sites still inject translated strings as raw HTML:

- `src/components/EmptyState.tsx:38` and `:99`
- `src/components/ConflictModal.tsx:69`

The severity is **low**, not critical: these are project-controlled locale files,
not user or agent content — and the original, genuinely dangerous case flagged in
`AUDIT.md` (rendering compiled task markdown through `dangerouslySetInnerHTML` in
the old `MarkdownEditor.tsx`) is gone, since editing moved to BlockNote.

It still deserves closing. kandown ships 48 locales; a translation contributed
through a PR is a plausible injection path, and interpolated values like
`{{taskId}}` come from the board.

## Subtasks

- [ ] Replace the three call sites with `<Trans>` components or explicit JSX so no
      raw HTML is injected at all — preferred over adding a sanitizer dependency
- [ ] If any case genuinely needs HTML, escape the interpolated values first
- [ ] Add a lint rule banning new `dangerouslySetInnerHTML` once ESLint lands ([[t229]])

## Notes

Source: `AUDIT.md` §3 Vulnérabilités applicatives. The path-traversal and `axios`
findings from that same audit are both already resolved.
