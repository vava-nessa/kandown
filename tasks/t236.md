# Validate task frontmatter at parse time

## Context

Task frontmatter is written by humans *and* by AI agents, then parsed with a
hand-rolled YAML subset. Today an unexpected shape is coerced or dropped silently
rather than reported — the failure mode is a field quietly disappearing, which is
the worst possible one for a file-over-app tool where the file is the database.

## Subtasks

- [ ] Define the frontmatter contract explicitly (which fields, which types,
      which are optional) in one place next to `src/lib/types.ts`
- [ ] Validate on parse and surface a precise, actionable message
      (`t42: "priority" must be one of P1-P4, got "high"`) instead of coercing
- [ ] Preserve unknown keys verbatim on round-trip — never drop what was not understood
- [ ] Surface validation failures in `kandown doctor` as a board-wide report
- [ ] Decide between a small hand-written validator and adding `zod`
      — the CLI bundle size argues for hand-written; note the decision in the task

## Notes

Source: `ameliorations_ideas_audit` §38. `zod` is not currently a dependency.
Related: the "preserve unknown lines verbatim" rule was also the recommended
mitigation for the old parser data-loss bug — worth keeping as an invariant with a
test in [[t227]].
