# Turn the website demo into the local web app

## Context

Replace the separate demo concept with one honest web app entry point. The app
opens on a disposable sample project, explains that nothing is saved, and lets
compatible browsers switch to a real local Kandown project without an account
or server.

## Subtasks

- [x] Add a local-project mode to the website app build
  report: A successfully selected folder now disconnects the in-memory backend and hands all reads, writes, recents, and file watching to the existing File System Access implementation. Cancelling keeps the sample project untouched.
- [x] Put a prominent Open project action and demo notice inside the app
  report: The sample project now opens with a ten-second informational toast and keeps a large Open project button in the top toolbar until a local folder is loaded.
- [x] Rename Demo navigation and routes to App
  report: The public route and header navigation now use App, the old /demo URL redirects permanently, and the full-screen iframe shell keeps the supporting sample build as an internal detail.
- [x] Rewrite homepage CTAs around free, local, no-login web access
  report: The hero and closing CTA now open Kandown Web and emphasize free access, no login, and local project files.
- [x] Explain the web experience limitations clearly
  report: Both homepage CTA areas identify the web app as a lightweight companion and point to the TUI and CLI for agent launching, automation, and the full workflow.
- [x] Turn the sample project into a categorized interactive Kandown guide
  report: Replaced filler product tasks with eight hands-on guide cards covering basics, Markdown formatting, local ownership, long-running agents, handoffs, dependencies, search, and the Web/TUI/CLI split. Tags provide clear categories with restrained humor and emojis.
- [x] Verify local opening, fallback demo, responsive UI, typecheck and build
  report: Verified the sample boot, toast, Open project entry point, categorized guide, desktop homepage, and 390 px layouts in Chromium. Root and website typechecks, the generated codemap check, the embedded app build, website production build, SSR, and all 43 prerendered pages pass. The native operating-system directory choice remains an intentional manual interaction.
