## Goal

Bring the extension system (engine + CLI + daemon API shipped in t273) to the web
UI: contributed field editors in the task drawer, card badges, an Extensions
settings panel, and extension gates respected on web moves.

## Why now

t273 shipped the engine, the CLI surface and the daemon API
(`/api/extensions`, `/api/extensions/<id>/{enable,disable}`,
`/api/tasks/<id>/field`). The web UI does not yet consume any of it: moves apply
the dependency gate client-side in `boardSlice` and write the file directly, so
extension gates are bypassed on the web; contributed fields and badges are not
rendered; there is no management UI.

## Scope

- **Gate-in-move (web):** add a daemon `POST /api/tasks/<id>/move` that runs the
  dependency gate AND extension gates, then writes; refactor
  `src/lib/store/boardSlice.ts` `moveTask` to call it instead of gating
  client-side and writing directly (centralises the single mutation authority).
- **Field editor:** render contributed fields in the task drawer (read
  `plugins.<id>.*` via the existing `frontmatter` already on the card; edit via
  `POST /api/tasks/<id>/field`). Use the field's declared `type` for the input.
- **Card badge:** render contributed field `badge()` outputs on `Card.tsx`. Badge
  functions are Node-side, so expose computed badges via `/api/extensions`
  metadata or a small render route.
- **Extensions settings panel:** list extensions (from `/api/extensions`) with
  health, contributions, enable/disable, install (local path), and a restricted
  mode toggle.
- **Web panel mounting (P1 stretch):** dynamically import an extension's web
  bundle served at `/api/extensions/<id>/files/web.js` and render it in a Drawer
  panel inside a per-panel `ErrorBoundary`. Scoped API via postMessage or a
  prop-injected context.

Out of scope: iframe sandbox hardening (deferred per ADR 0002), kandown.dev
submit form (separate website repo).

## Acceptance criteria

1. A web move to `Done` on a task without points is blocked by the burndown gate
   with the reason shown, matching the CLI.
2. The task drawer shows a "Story points" editor for the burndown `points` field;
   editing persists `plugins.burndown.points` and the card shows the `🔺 N` badge.
3. Settings has an Extensions section listing installed extensions with
   enable/disable working and restricted mode togger.
4. `pnpm typecheck`, `pnpm build`, `pnpm test` pass.

## Subtasks

- [ ] Daemon `POST /api/tasks/<id>/move` (dep gate + extension gates + write)
- [ ] Refactor `boardSlice.moveTask` to use the move endpoint
- [ ] Drawer: contributed field editors (typed input, save via setField)
- [ ] `Card.tsx`: contributed field badges
- [ ] Settings: Extensions panel (list / enable / disable / restricted toggle)
- [ ] (stretch) Web panel mounting via `/api/extensions/<id>/files/web.js`
- [ ] Verify typecheck + build + test

## Decisions

- Web moves go through the daemon so extension gates run server-side (single
  mutation authority, docs/EXTENSIONS.md § "Runtimes").
- Badge rendering stays Node-side (the badge function is author code); the web
  fetches computed badges rather than re-implementing them.
