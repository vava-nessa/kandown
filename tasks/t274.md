## Goal

Bring the extension system (engine + CLI + daemon API shipped in t273) to the web
UI: contributed field editors in the task drawer, card badges, an Extensions
settings panel, and extension gates respected on web moves.

## Why now

t273 shipped the engine, the CLI surface and the daemon API
(`/api/extensions`, `/api/extensions/<id>/{enable,disable}`,
`/api/tasks/<id>/field`). The web UI does not yet consume any of it: moves apply
the dependency gate client-side in `boardSlice` and write the file directly, so
extension gates are bypassed on the web; contributed fields and badges are not
rendered; there is no management UI.

## Scope

- ✅ **Settings Extensions panel** (done in this pass): a new Extensions section
  lists every installed extension with health + contributions, enables/disables
  per extension, and toggles restricted mode. Backed by `serverListExtensions /
  serverEnableExtension / serverDisableExtension` in `filesystem.ts` and the
  daemon `/api/extensions` routes. `KandownConfig` gained `extensions.restricted`.
  Verified end to end via Chrome DevTools.
- ✅ **Gate-in-move (web):** the daemon `POST /api/tasks/<id>/move` composes the
  dependency gate and extension gates, persists status/order, then dispatches
  post-move handlers. Both the live store and sliced store keep optimistic UI
  with complete rollback; standalone keeps the core gate and degrades extension
  gates open.
- ✅ **Field editor:** the previous mount failure was traced to two intentionally
  exclusive editors, not memoization: desktop task routes render
  `TaskWorkspace`, while `Drawer` returns null on desktop. The shared
  `TaskExtensionSurface` now mounts after Report in both editors and writes only
  registered `plugins.<id>.<key>` fields.
- ✅ **Card badges:** Node computes all badges in one pass through
  `/api/extensions`, avoiding N+1 browser calls. Standalone executes the bundled
  project-local `index.js` registration entry and computes the same badge funcs.
- ✅ **Web panel mounting:** self-contained panel bundles load through
  authenticated fetch + Blob import and render as collapsible sections inside a
  per-panel `ErrorBoundary`. Panels receive a frozen task, scoped field/refresh
  API and the host React runtime. Three consecutive crashes persist quarantine.

Out of scope: iframe sandbox hardening (deferred per ADR 0002), kandown.dev
submit form (separate website repo).

## Acceptance criteria

1. A web move to `Done` on a task without points is blocked by the burndown gate
   with the reason shown, matching the CLI.
2. The task drawer shows a "Story points" editor for the burndown `points` field;
   editing persists `plugins.burndown.points` and the card shows the `🔺 N` badge.
3. Settings has an Extensions section listing installed extensions with
   enable/disable working and restricted mode toggle.
4. `pnpm typecheck`, `pnpm build`, `pnpm test` pass.

## Decisions

- Web moves go through the daemon so extension gates run server-side (single
  mutation authority, docs/EXTENSIONS.md § "Runtimes").
- Badge rendering stays Node-side (the badge function is author code); the web
  fetches computed badges rather than re-implementing them.
- Full standalone parity: fields, badges and web panels remain usable through
  the File System Access bridge; authoritative gates degrade gracefully without
  a daemon rather than breaking the board.
- Web panels render as collapsible sections after extension fields in the task
  editor. Each panel gets its own ErrorBoundary.
- A crashing panel shows a placeholder immediately and reports the failure; the
  owning extension is persistently quarantined after 3 crashes.
