# Fix sidebar task switch not updating BlockNote editor body

## Context

In the desktop task workspace, opening a task and then picking a different task from the left sidebar explorer only refreshed the title — the description and report (BlockNote editors) kept showing the previous task's content. Users had to hit Back to fully close the workspace and then click the card to open the new task, which is a heavy-handed workaround.

## Subtasks

- [x] Reproduce the bug in the running daemon
  report: Opened t213, then switched to t214 via the sidebar — title updated but the description still showed t213's body. Confirmed on t213 → t214 → t213 round-trip too.
- [x] Fix `BlockNoteMarkdownEditor` to react to external value changes
  report: Replaced the `useEffect(..., [])` with a `useEffect(..., [value, editor])` that compares the incoming value against the editor's own current markdown (same normalization as the onChange path) and only calls `replaceBlocks` when they differ. This preserves the cursor/focus during typing and correctly reloads on task switch.
- [x] Verify typecheck, build, and end-to-end behavior
  report: `pnpm typecheck` and `pnpm build` both pass. End-to-end manual test: switching tasks via the sidebar now updates title + body + report atomically; typing in the body does not reset the editor; round-trips between two tasks work both ways.
