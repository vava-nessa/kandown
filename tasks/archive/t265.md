# [website] Changelogs page — sidebar versions, one URL per release

## Context

The product already ships a per-release file under `changelogs/vX.Y.Z.md` plus a
generated root index (`CHANGELOG.md`). The marketing site did not expose any
of it. vava wanted a `/changelogs` page so a visitor can browse the history
without leaving, with a discreet footer link as the only entry point.

The architecture mirrors `build-llms.mjs`: the Markdown files are the source
of truth, the site prerenders every route, and a build step turns Markdown
into static assets under `public/`. The prerenderer follows `crawlLinks`,
so emitting one HTML per release and linking them from the index page
prerenders the whole tree without extra configuration.
