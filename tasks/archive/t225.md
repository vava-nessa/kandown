report: |
  ## Problem
  When starting `kandown` from a parent directory that contains a subdirectory with a `.kandown/` folder, the CLI would not find it — it only looked in the current working directory itself.

  ## Fix
  Modified `findKandownDir` in `src/cli/lib/config.ts` and `resolveKandownDir` in `src/cli/cli.ts` to recursively search subdirectories when no `.kandown/` is found in the cwd.

  The search:
  1. Checks the cwd directly (unchanged).
  2. Recurses into non-hidden subdirectories (skipping `.`, `..`, `node_modules`, and `tasks` to avoid noise).
  3. Returns the first `.kandown/` found at any depth.
  4. Falls back to `resolve(cwd, '.kandown')` if nothing is found (triggering auto-init).

  ## Validation
  - Build passed: `pnpm build` ✅
  - Logic tested: `findKandownDir('/tmp/test-kandown-search')` → `/tmp/test-kandown-search/subproject/.kandown` ✅
  - Skipped paths: `.`, `..`, `node_modules`, `tasks` are correctly excluded.

  ## Files
  - `src/cli/lib/config.ts` — `findKandownDir` now recurses into subdirectories.
  - `src/cli/cli.ts` — `resolveKandownDir` now uses the same recursive search.
