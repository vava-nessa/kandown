# Make the website light-only

## Context

Give Kandown one strong visual identity and guarantee that operating-system dark
mode can never change the website appearance. Remove the public toggle, stored
theme preference, dark CSS tokens, dark shader path, and dark syntax switching.

## Subtasks

- [x] Audit every website dark-mode entry point
  report: Located the header toggle, pre-paint localStorage script, OS media queries, explicit data-theme selectors, dual browser theme colors, shader theme listener, dark utility variants, Shiki overrides, and theme documentation.
- [x] Remove runtime theme selection and dark-only source files
  report: Removed the header toggle, pre-paint localStorage script, stored/system theme resolver, hydration exception, and dual browser theme-color tags. Deleted ThemeToggler.tsx and lib/theme.ts because they had no light-only responsibility left.
- [x] Reduce CSS, shader, syntax highlighting, and browser chrome to light-only
  report: Removed all dark token layers, data-theme selectors, OS dark media queries, dark Tailwind variants, theme View Transition CSS, shader theme observers and dark props, and dual Shiki output. Native controls and browser chrome now declare light only.
- [x] Update the website design documentation
  report: Replaced the old three-layer theme and toggle documentation with the light-only identity contract, including fixed browser chrome, native controls, Shiki, black recording frames, and the explicit guarantee that device preference cannot override the site.
- [x] Verify light rendering while the device preference is dark
  report: On the browser test device, prefers-color-scheme dark returned true while the website rendered rgb(255,255,255), reported color-scheme light, had no data-theme attribute, exposed no theme toggle, and kept a fixed #ffffff browser theme color. Desktop and mobile remained overflow-free. The embedded demo was rebuilt and its compiled seed contains theme:"light".
