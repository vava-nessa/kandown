# Fix project resolution selecting templates instead of root .kandown

## Context

Launching Kandown from this repository incorrectly scans child directories, skips the hidden root `.kandown/`, and selects `templates/kandown.json`. The live daemon consequently exposes the starter template as a project named `templates` instead of using the real root `tasks/` board.

## Subtasks

- [x] Replace recursive child scanning with current-directory/ancestor `.kandown` resolution.
  report: Updated `resolveKandownDir` to honor explicit paths, then walk upward for the nearest valid `.kandown/kandown.json`; it no longer scans child directories or mistakes packaged templates for a live project.
- [x] Remove runtime/generated artefacts accidentally committed under `templates/` while preserving init seeds.
  report: Stopped the template daemon, removed `templates/daemon.json` and `templates/kandown.html`, and added targeted ignore rules. Kept `templates/kandown.json`, agent docs, README, and starter tasks because `kandown init` consumes them.
- [x] Rebuild and verify root and nested-directory project resolution.
  report: `pnpm build` passes. CLI listing from the repo root, `src/`, `templates/`, and `.kandown/` consistently resolves the real root board (`t246` present, seed `t1` absent).
- [x] Replace the daemon attached to `templates` with one attached to the root `.kandown/`.
  report: Stopped PID 5361 and its stale template TUI chain, then started PID 54331 on port 2051. `/api/daemon` now reports `/Users/vava/Documents/GitHub/kandown/.kandown`, and `/api/tasks` serves the real root tasks.
- [x] Review the final diff and document completion.
  report: Reviewed the scoped source/config/docs diff with no correctness or security finding. Source diff whitespace checks pass; the full `git diff --check` only reports a trailing tab inside the generated single-file `.kandown/kandown.html` bundle.
