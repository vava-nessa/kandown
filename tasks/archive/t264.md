# [tui] Refactor TUI — list view by default, Tab toggles board/list

## Context

The kanban column TUI is cramped: at 5 columns on an 80-col terminal each card
gets ~15 usable characters, so every title is truncated to noise. The web UI
already has a `ViewMode = 'board' | 'list'` concept; the TUI has only the board.

vava asked for the Ableton model: **two views over the same data**, switched with
`Tab`, with the **list view as the default**. Reference is the taskwarrior-tui
layout — one task per line, dense columns (ID / Age / Status / Tags /
Description), plus a Name/Value detail pane pinned at the bottom that follows
the selection.

### Decisions (grilled with vava, 2026-07-26)

| Question | Decision |
|---|---|
| Age source | New `updated:` frontmatter field, stamped by **every** mutation. Fallback chain `updated ?? created ?? file mtime`. Chosen over raw mtime because `git clone` resets mtime and every task would read the same age. |
| List scope | Flat — **all** tasks from all columns in one list, with a coloured `Status` column. Not grouped, not per-column. |
| Detail pane | Split: list on top, live Name/Value pane at the bottom following the selection. `z` toggles it. `Enter` still opens the full-screen scrollable detail. |
| Columns | ID · Age · Status · Pri/Owner/Deps · Tags · Description. Tags kept per vava's written brief even though it was unticked in the poll. |
| Row overflow | Selected row wraps onto extra lines so the full title is readable; every other row stays exactly 1 line, truncated with `…`. |

### Bug found while reading the code

`searchQuery` (`/`) and `filterMode` (`f`) are stored in `board.tsx` state and
shown in the cheatsheet, but **never applied to the rendered tasks** — both
features are dead today. The refactor rebuilds them as a real filter pipeline
shared by both views.

## Subtasks

- [x] Add `updated:` to `TaskFrontmatter` + a shared `src/lib/task-meta.ts`
      (`stampUpdated`, `taskTimestamp`, `formatAge`)
      report: `src/lib/task-meta.ts` owns the field end to end. `nowStamp` emits
      UTC ISO trimmed to whole seconds (no ms — three characters of git diff
      noise per write, and nothing reads below seconds). `taskTimestamp` walks
      `updated → created → mtime` so pre-existing tasks keep working. Also added
      `BoardTask.updatedAt` in the parser and stripped `updated` from the generic
      `metadata` spread, otherwise every web card would print a raw ISO string.
- [x] Stamp `updated` at every write site: CLI board-reader (move/create/archive),
      `commands/tasks.ts` (create/assign/import), `lib/mcp.ts`, and the web
      `filesystem.ts` (write/archive/unarchive)
      report: 13 call sites. `serializeTaskFile` was deliberately left pure —
      stamping there would make every parser round-trip test time-dependent
      (t227) and would touch tasks that were only re-read. Verified end to end:
      `kandown move t264 Backlog` wrote `updated: 2026-07-26T08:54:35Z`.
- [x] Add a `tui` config section (`defaultView`, `showDetailPane`, `listSort`)
      to `config.ts` + `templates/kandown.json`
      report: Defaults are `list` / `true` / `status`. Confirmed by round-trip
      test that `saveConfig` preserves keys the CLI type does not model (custom
      skins, `agent.workOutput`, `board.columnColors`).
- [x] Build `screens/board/list-helpers.ts` — flatten, filter, sort, adaptive
      column layout, word wrap
      report: `computeListLayout` starts with every column on and drops them in
      a fixed priority order (tags → deps → owner → priority → age → status)
      until the description has ≥24 cells, so there are no width breakpoints to
      keep in sync. Verified at 120 / 100 / 80 / 62 columns.
- [x] Build `screens/board/list-view.tsx` — `TaskListView` + `TaskDetailPane`
      report: `computeListGeometry` is the single source of truth for row
      positions, fed to both the renderer and the click handler — the same
      "one function, two callers" discipline as `computeScrollIdx`. Unlike the
      kanban column, the scroll offset persists across renders instead of being
      re-derived, which stops the selection being pinned to the bottom edge.
- [x] Wire `view` state + `Tab` toggle into `board.tsx`, preserving the focused
      task across the switch and persisting the choice to config
      report: The selection is reconciled **by task id**, not index — the list is
      one flat ordering and the board is many, so an index would land on an
      unrelated task. Switching also drops board-only transient modes (context
      menu, half-finished move).
- [x] Rebrand `/` search and `f` filter so they actually filter both views
      report: `applyBoardFilter` derives the filtered board once; every view,
      hit-test and navigation bound reads it. The dependency gate keeps reading
      the **unfiltered** `rawBoard` — resolving it against the filtered board
      would let you unlock a blocked move just by typing in the search box.
      Added a `blocked` filter mode and made `Esc` clear search/filter before it
      quits.
- [x] Wheel-scroll support in the list (parser already emits `scroll`, needs a
      direction field)
      report: Added `wheel: 'up' | 'down'` to `MouseInputEvent` — SGR encodes the
      wheel as buttons 4/5 but `button` is clamped to 0-2 for click handling, so
      the direction was unrecoverable. Click selects, click again opens.
- [x] Update the cheatsheet, the JSDoc headers, README and CHANGELOG
      report: Cheatsheet split into "Both views / List view / Board view".
      README gained an ASCII sample of the list and the full key table.
      `pnpm codemap:check` → 157 files, 100% documented.

## Report

Done. `pnpm typecheck` and `pnpm build` are green; the TUI was smoke-tested in a
real pty (list boots by default, `Tab` round-trips to the board and back, `f`
filters to 17 P1 tasks, `s` cycles the sort, `z` hides the pane, the selected row
wraps over three lines, `↪1` and `✓` chips render, and the footer counter stays
consistent with the cursor).

Two side notes for whoever picks this up:

- The `Age` column only becomes precise once a task is written by kandown at
  least once — until then it falls back to day-precision `created`. Nothing to
  fix, but it means a fresh repo shows a lot of identical `1d` values.
- `tui.defaultView` is written on every `Tab`. That is one small
  `kandown.json` write per toggle; if it ever shows up as churn, debouncing it
  is the obvious fix.

## Notes

`computeScrollIdx` in `board/helpers.ts` is shared between the render path and
mouse hit-testing so they can't diverge — the list view needs its own, simpler
equivalent (fixed 1-line rows except the selected one), and must keep the same
"one function, two callers" discipline.
