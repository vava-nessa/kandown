## Changes
- New `SubtaskEditor` component hosts the checklist (toggle, edit, enter-to-insert, backspace-to-remove, expand description/report) and an **Add subtask** button. It owns the section UI but delegates persistence to the drawer/workspace through the existing autosave.
- The mobile `Drawer` and the desktop `TaskWorkspace` now mount `SubtaskEditor` between Description and Report, replacing the prior "no subtask editor" gap. The handler is declared above the desktop early return so the rules of hooks stay valid on both viewports.
- Header progress chip (`X/Y done`) appears in both editor surfaces when the task has subtasks.
- `extractSubtasks` now preserves unrelated prose inside the `## Subtasks` section, supports multi-line `[DESC]`/`[REPORT]` markers (and the legacy `description:`/`report:` indented lines), and treats `- [ ]` (empty text) as a valid row so a new step can be created without supplying text first.
- `injectSubtasks` rewrites only the checklist section and keeps the section's title and any surrounding sections, blank lines, and prose in their original order. An empty `subtasks: []` call removes the section cleanly when the last item is removed.
- All checklist buttons received `type="button"` and `aria-label` translations (`subtask.markDone`/`markOpen`/`expand`/`collapse`/`remove`) for keyboard users.

## Decisions
- Kept the existing `[DESC]` / `[REPORT]` canonical format (with a blank line prefix for multi-line content) so agents and the UI continue to share the same source of truth.
- The 1-vs-2 click model matches the surrounding card/drawer actions: drawer toggles are instant, archive is one click, and the only two-click guard remains on destructive delete.
