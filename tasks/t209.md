# Verify and harden auto-updater before release bump

## Context

Vava asked to bump but first verify why `kandown` auto-update can feel blocked when multiple projects are open.

## Subtasks

- [x] Inspect auto-update lock/cache behavior
  report: Found failed install attempts were throttled for 24h after a successful npm registry answer, making retries feel blocked.
- [x] Fix failed update retry throttling
  report: Moved rememberUpdateCheck so only up-to-date checks and successful installed updates are cached.
- [x] Refresh all open project HTML bundles after auto-update
  report: Added daemon-port scanning that refreshes kandown.html for every open project after an in-place global update.
- [x] Verify scripted CLI commands exit cleanly
  report: Ran gtimeout-wrapped doctor and list --json; both exited with code 0 and produced expected output.
- [x] Simulate an installed older CLI auto-update path
  report: Created a temporary no-src installed package at v0.21.9 under .tmp-auto-update and verified a TTY run detected v0.22.0, installed, printed changelog, and restarted.
- [x] Run build validation
  report: Ran pnpm typecheck and pnpm build successfully before starting the release bump.
- [x] Final completion report
  report: Added frontmatter completion summary with changes, decisions, validation, and affected files.
